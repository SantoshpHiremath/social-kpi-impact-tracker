# Social KPI & Departmental Impact Tracker

A tested Python pipeline that tracks progress on a workplace-accessibility and inclusion initiative and links its social KPIs to departmental performance. It measures the initiative's progress and connects it to operational metrics by department and quarter, so leadership can see whether the two move together.

## What it does

The pipeline generates quarterly, per-department accessibility/inclusion data (workforce representation, workplace-accommodation requests and completions, accessibility-training completion), validates it for real data-quality problems, computes progress KPIs, explicitly joins those KPIs to departmental performance metrics (on-time delivery, employee engagement, voluntary attrition) by department and quarter, and writes everything into a formatted, multi-sheet Excel tracking report.

The join is done carefully: matching department and quarter exactly rather than concatenating two tables, and validating the program data first, since accessibility/HR data has realistic failure modes (a completions count higher than the requests count because of a reporting carryover error, or a training metric a department has not yet reported for the current quarter).

- **`src/data_sources.py`**: generates synthetic quarterly accessibility/inclusion records across 6 departments and 6 quarters, plus separate departmental performance records. It deliberately injects two realistic problems: one record where completed workplace accommodations exceed requested accommodations in the same quarter (completions carried over from a prior quarter and counted in the wrong period), and one record with a missing training-completion percentage (a metric not yet reported, not something to silently treat as 0%).
- **`src/data_quality.py`**: flags both injected problem types before any KPI is computed from them: accommodation overcounts and missing training metrics.
- **`src/kpi_linkage.py`**: computes the accessibility-program progress KPIs (workforce representation %, accommodation fulfillment %, training completion %), excludes flagged overcount rows from the fulfillment-rate calculation (a rate above 100% is not a meaningful KPI), and joins the result to departmental performance records via an explicit `(department, quarter)` key rather than a positional zip, so a missing or mismatched quarter is skipped instead of paired with the wrong data. It also produces a per-department quarter-over-quarter trend view, since a leadership report needs progress over time, not just a snapshot.
- **`src/report.py`**: writes a formatted `.xlsx` workbook (via `openpyxl`) with three sheets: Summary, Accessibility & Performance (the linked view), and Data Quality Flags.
- **`run_pipeline.py`**: runs the full flow end to end and prints a console report.

## Data

All department names, headcounts, and metrics are fictional and generated by `src/data_sources.py`. The method is general: it models the shape of workplace-accessibility program tracking using common CSR reporting concepts (representation, accommodation fulfillment, training completion), so real program data can be dropped in. The relationship between program maturity and departmental performance in the synthetic data is loosely modeled for realism.

## Tests

33 automated tests (`tests/`), all passing, covering:

- Data generation reproducibility, including a bug I found and fixed in the reproducibility test itself: `NaN != NaN` in Python, so the naive dataclass-equality check failed on the deliberately injected missing-metric row even though the data was identical. The fix compares fields individually with a NaN-aware check.
- Data-quality flagging (correctly flags both injected issues and nothing else).
- KPI computation (representation and fulfillment percentages, including the divide-by-zero and overcount edge cases).
- The department/quarter join (correctly matches, and skips unmatched department/quarter combinations rather than fabricating a pairing).
- The trend view.
- The Excel report itself (the file is created, contains the expected sheets, and the data in each sheet matches the input).

## Project structure

```
src/data_sources.py   synthetic data generator
src/data_quality.py   data-quality flags
src/kpi_linkage.py    KPI computation and department/quarter join
src/report.py         Excel report writer
run_pipeline.py       end-to-end runner
tests/                pytest suite
output/               generated Excel report
```

## Running it

```bash
python3 -m pytest -v      # 33 tests, all passing
python3 run_pipeline.py   # runs the full pipeline, writes output/social_kpi_impact_report.xlsx
```
